# 窗口缩放与正文浏览器失效回归

2026-10-02，目标 IDEA IU-262.10968.63，Windows / 配套 JBR。

用户安装后的只读诊断未发现 Java 堆溢出：采样时使用约 557 MiB，堆上限 4 GiB；UI 线程在等待事件。私有 JCEF 日志明确记录回调通道断开，随后网桥继续使用 READY 状态的旧浏览器，反复等待并超时。这个采样不能用来判断全部原生内存是否存在泄漏。

隔离测试还复现了两处缺陷：连续缩放后网页尺寸变化但实际位图停留在旧尺寸；故意终止测试浏览器进程后，Windows 管道写入阻塞并持有 RPC 锁，清理与新运行时创建无法完成。上一轮仅断言 JS 视口大小，未覆盖这些实际画面与异常生命周期路径。

修复内容：

- 尺寸通知合并到 40 ms；首次重绘后核对实际帧的尺寸和帧序号，100 ms 检查一次，最多补发 20 次，得到目标帧立即停止。没有整页重载。
- 共享栅格元数据和读取串行处理；先解开原生内存锁，再取得绘图锁。绘图锁与浏览器请求锁分离；异常不会从绘制回调传播并关闭整个通道。
- Windows 的私有前向 IPC 使用独立本机 TCP 端口，排除 IDE 已选择但可能尚未监听的默认端口；不连接 IDE 自带的浏览器实例。其他平台保留原有传输。
- 监听通道断开和私有进程退出，失效实例不再复用；网桥结束当前失败请求。正文启动在后台执行并有等待上限；关闭窗口和过期启动回调释放浏览器。
- 正文显示“重试正文浏览器”，点击后重新创建私有运行时并恢复缓存话题及楼层；不重放帖子写操作。清理不在回调线程中执行，进程退出独立完成终止信号。
